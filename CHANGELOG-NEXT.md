## 正體中文

### feat

- diff 的未變更區段可以從 gutter 收合與展開：以前展開是單向的，多開了一段想收回去只能重開分頁，因為 @codemirror/merge 展開時就把那條「N 行未變更」的橫條吃掉了。現在窗格邊緣多一條專屬的 gutter，每條橫條旁邊有展開圖示、已展開區段的第一行有收合圖示，兩者都沒有的檔案不佔任何寬度；並排模式下左右兩側成對連動。留言的加號同時改成對話框圖示，因為隔一欄的變更 gutter 已經用加號標示新增行，兩個加號並排會被誤認成同一個控制項 (#393)
- diff 分頁可以在並排與行內之間切換：並排會把每份文件能用的寬度砍半，窄窗格、分割分頁或長行的檔案讀起來只能靠換行或橫向捲動。行內模式只留新的那份文件、把舊的行畫在新的行上面，和 git diff 印出來的樣子一致。標題列那顆按鈕畫的是切過去會變成的模式，所以不需要判讀按鈕有沒有被按下。選擇記在全域，因為想用哪種方式讀是偏好而不是某個檔的屬性；變更跳轉、逐行留言、未變更收合在兩種模式都能用 (#392)
- 原始碼控制面板的近期提交固定在底部，版面也會被記住：以前收合時標題釘在面板最底，一展開卻回到 Changes 底下的正常捲動流，變更清單一長，剛點開的標題就被捲出視野，而且沒辦法把歷史區調高或調低。現在它在兩種狀態下都是釘在底部的獨立窗格，展開時往上開並帶自己的捲軸，可從上緣拖曳調整（60 到 600px，另外上限是面板的 70%，避免把 Changes 擠出畫面）。窗格高度、哪些區塊被收合、以及扁平或資料夾檢視都會記住；Git Graph 的提交詳情面板用另一個 key 記自己的切換，因為兩份清單的寬度差距很大，共用一個偏好兩邊都不合 (#380)
- Apple Intelligence 成為可選的預設模型（macOS 26 以上且系統已啟用時才會出現，Windows 不會看到這個選項）：選定後 commit message 產生、diff 解釋與行內補完都改由裝置上的模型回答，不需金鑰、資料不離開本機。AI 助手面板刻意不提供它——預設是 Apple Intelligence 時，對話會改用面板上另選的雲端模型，且切換不影響預設值 (#395)
- Ports 面板全面翻新：清單改依 port 排序、不再每次輪詢重新洗牌；port 依專案分組（cwd 目錄名為組標題、其他程序墊底），每列以白話的服務名稱開頭（Vite dev server、Next.js dev server、PostgreSQL 等），CPU 與記憶體移入展開詳情；macOS 26 以上且開啟 Apple Intelligence 時，動作列第一顆是「詢問 AI」，由裝置上的模型直接說明該行程與是否可安全停止，回答以 markdown 樣式呈現，資料不離開本機 (#388, #391)
### fix

- diff 的 gutter 圖示改成與行號對齊：留言圖示和收合展開箭頭原本會撐滿 gutter 元素再垂直居中，而 gutter 元素帶的是整個行區塊的高度，不是一行文字的高度。單一行時兩者相同，所以當初看起來是對的，但只要區塊比一行高，圖示就會掉到區塊中央，而行號留在第一行。會讓區塊變高的情況有三種：自動換行遇到長行、那一行掛了評論卡片或輸入框、以及並排模式下 merge view 為了讓兩側對齊而插入的墊高塊。現在兩處都以一行文字為居中的框 (#404)
- 大檔的 diff 不再被畫成整份刪掉重寫：一個 13,890 行的資源檔只加了 24 行，diff 分頁卻顯示成整份刪除再整份新增，和面板上同一列寫的 +24 −0 對不起來，而錯的是分頁那邊。原因是比對函式庫預設拿差異範圍的大小當放棄門檻，但實際成本來自差異的數量，少量變更散在大檔裡算起來很便宜，卻剛好踩中那個門檻。改成以時間為預算，超過一秒才退讓。實測那個 450KB 的檔，預設會把 107,763 個字元誤標成刪除，改完之後精確且只花 11 毫秒 (#402)
- diff 的 gutter 滑鼠提示不再殘留在畫面上：那塊提示掛在頁面最外層，靠圖示自己的滑出事件收掉，但指標還停在上面而圖示先被拆掉時，滑出事件永遠不會送出。diff 分頁在視窗重新取得焦點時會重讀兩側內容並重建編輯器，所以指標停在收合箭頭或留言圖示上、切到別的 app 再切回來，提示就會留到分頁關掉為止。現在提示開著時會定期確認圖示還在文件上，不在就自己收掉 (#401)
- diff 分頁的字級跟著字型設定走：設定裡的「字級大小」本來只影響編輯器分頁和終端機，diff 分頁固定在 13px，所以把整個 app 的字調大之後，只有 diff 還是原本的小字。現在並排與行內都吃這個設定；設定的預設值本來就是 13，所以不動設定的話畫面與以前完全相同 (#400)
- diff 分頁的標題列控制項移到右側，與其他窗格一致：變更跳轉、自動換行、送給 agent 那幾顆原本停在標題列左半邊的末端，剛好落在兩份文件的分界上。在分割分頁裡窗格關閉鈕仍在最右邊，整條讀起來就是檔名、中間一堆按鈕、然後關閉鈕自己孤零零在旁邊；而且那幾顆是對整份 diff 生效而不是只對左邊那個檔，停在中線容易讓人誤會。第一次出現的留言提示也跟著移到右側 (#390)
- 原始碼控制面板的資料夾整個標籤都能點開闔：資料夾檢視下原本只有 13px 的箭頭可以開闔，點資料夾圖示或名稱這兩個最直覺、也佔掉大半列寬的位置卻沒有反應，看起來像壞掉的列而不是收起來的列。現在箭頭、圖示、名稱是同一顆橫跨整列的按鈕，子樹的動作鈕仍是獨立的，所以暫存或取消暫存一個資料夾不會順手把它闔起來。hover 不改文字顏色，因為在這份清單裡亮起來的標籤代表「正在看的那個檔」，hover 不該模仿那個狀態 (#381)
- 修正 Worktree 面板無法移除「目錄已不存在」項目的問題。先前按移除會執行 git worktree remove，部分 git 版本（如 Apple Git 2.50）會因驗證目錄失敗而報錯；現改走 git worktree prune，任何版本都能把殘留紀錄清掉，一般 worktree 的移除行為不變 (#386)

## English

### feat

- Collapsed unchanged stretches in a diff fold and unfold from a gutter of their own. Expanding used to be one-way: `@codemirror/merge` consumes its "N unchanged lines" bar on the way out, so a file opened one stretch too many stayed that way until the tab was reopened. A dedicated gutter at the pane edge now carries an unfold icon beside each bar and a fold icon on the first line of every stretch that is open, and costs no width in a file that has neither; in a split, the two sides pair up one for one. The review-comment "+" becomes a speech bubble in the same pass, since the change gutter one column over already marks added lines with "+" and two plus signs side by side read as the same control (#393)
- A diff tab switches between side-by-side and inline. Side by side halves the width each document gets, so on a narrow pane, a split tab, or a file with long lines, reading a change means wrapping or scrolling lines that would otherwise fit. Inline keeps only the new document and draws the old lines in above the new ones, the way `git diff` prints it. The header control names and draws the mode it switches to, so there is no pressed state to interpret. The choice is remembered app-wide, since which mode to read in is a preference rather than something about one file; chunk navigation, review comments and the collapsed-unchanged bars work in both (#392)
- Recent commits is pinned to the bottom of the Source Control panel, and the panel's layout is remembered. Collapsed, its header used to sit at the very bottom; expanding moved it back into the normal scroll flow under Changes, so with a long Changes list the header you had just clicked scrolled out of view, and there was no way to make the history taller or shorter. It is now its own pane, pinned in both states, opening upward with its own scrollbar and drag-resizable from its top edge (60 to 600px, additionally capped at 70% of the panel so a squeezed panel can never push Changes off the top). The pane height, the set of collapsed sections and the flat/folder view mode all persist; the Git Graph commit details panel keeps its own toggle under a separate key, because the two lists live at very different widths and one shared preference would fit neither (#380)
- Apple Intelligence becomes a selectable default model (shown only on macOS 26+ with the system model available; Windows never sees the option): commit message generation, diff explains and inline completion then run on-device, keyless, with nothing leaving the machine. The AI assistant panel deliberately excludes it — with an Apple default, conversations use a separately chosen cloud model and switching it never touches the default (#395)
- The Ports panel is reworked: the list is sorted by port and no longer reshuffles on every poll; ports are grouped by project (cwd basename as sticky headers, other processes last), rows lead with plain-English service names (Vite dev server, Next.js dev server, PostgreSQL, …) and CPU/memory move into the expanded details; on macOS 26+ with Apple Intelligence enabled, the action row leads with an Ask-AI button answered by the on-device model — what the process is and whether stopping it is safe, rendered as markdown, with nothing leaving the machine (#388, #391)
### fix

- The diff gutter icons line up with the line number. The comment icon and the fold/unfold arrows each filled their gutter element and centred inside it, but a gutter element carries the height of the whole line block rather than of one text row. Those are the same thing for a plain one-row line, which is why it looked right; they diverge as soon as a block is taller, and then the icon lands at the middle of the block while the number stays on the first row. Three things make a block taller: word wrap on a long line, a comment card or the draft box under the line, and the spacer the merge view inserts to keep the two sides of a split aligned. Both now take one text row as the box to centre in (#404)
- The diff of a big file is no longer drawn as the whole file deleted and added back. A 13,890-line resource file with 24 lines added rendered as an entire deletion followed by an entire insertion, against the `+24 −0` on its own row in the panel, and the tab was the one that was wrong. The diff library defaults to bailing out on the size of a differing range, but the real cost comes from the number of differences, so a few changes spread through a large file are cheap to diff exactly and yet trip a limit set on range size alone. The budget is now time, and only a scan past one second gives up. Measured on that 450KB file: the default marks 107,763 characters as deleted, where the new setting is exact in 11ms (#402)
- The diff gutter's hover hint no longer strands itself on screen. The hint lives on the body and is taken down by the icon's own `mouseleave`, which never fires for an icon removed while the pointer is still on it. The diff tab re-reads both sides whenever the window regains focus, rebuilding the editors, so parking the pointer on a fold arrow or a comment icon and alt-tabbing away left the hint up until the tab was closed. An open hint now checks that its icon is still in the document and takes itself down when it is not (#401)
- The diff tab's type follows the font setting. The font size in Settings sized editor tabs and terminals but not the diff, which was pinned at 13px, so sizing the app up left the diff behind in small type. Both side-by-side and inline now read the setting; 13 is the setting's own default, so nothing moves for anyone who has not changed it (#400)
- The diff pane's header controls move to the right, like every other pane. Chunk navigation, word wrap and send-to-agent sat at the end of the header's left half, landing on the split between the two documents. On a split tab the pane close button still sat at the far right, so the strip read as filename, then buttons in the middle, then a close button off on its own; and those buttons act on the whole diff rather than on the left file, so sitting on the midline suggested an ownership they do not have. The first-run review-comment hint follows them to the right edge (#390)
- A folder in the Source Control panel toggles from its whole label. In folder view only the 13px chevron toggled a folder; clicking the folder icon or its name, the obvious targets and most of the row's width, did nothing, which reads as a dead row rather than a collapsed one. The chevron, icon and name are now one button spanning the row, with the subtree action button still a sibling, so staging or unstaging a folder never toggles it. Hover does not change the text colour, because a bright label in this list means "this is the file you are viewing" and hover must not imitate that state (#381)
- Fix the Worktrees panel failing to remove an entry whose directory no longer exists. The remove button ran git worktree remove, which some git versions (e.g. Apple Git 2.50) reject with a validation error for a gone directory; stale rows now go through git worktree prune, which clears the record on every version, while normal removals keep their exact semantics (#386)
